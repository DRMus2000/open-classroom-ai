## 已确认的产品规则

| 编号 | 最终规则 |
|---|---|
| R01 | 只服务一个约 30 人的班级，1 名教师，教师具有完整管理权限。无多班、多租户和教师分工需求。 |
| R02 | 学生默认每天 3 次；每人独立；未使用次数不结转。按教师电脑操作系统时区对应的自然日计算，不能使用学生浏览器或学生个人资料的时区。 |
| R03 | 一次新的问答计一次，包括追问和明确发起的重新生成。首版每次只选一个课堂模型。HTTP 重传、刷新后重新订阅相同操作，不产生新计数和新模型调用。 |
| R04 | 教师拒绝扣 1 次；正常完成的回答扣 1 次。教师修改后批准仍是原请求，最多扣 1 次。 |
| R05 | 网络故障、模型错误、服务重启等导致的意外中断不扣，即使已经产生部分回答。不能沿用旧建议中的“所有部分输出均收费”。 |
| R06 | 学生主动停止且已经有可展示回答，扣 1 次；尚无可展示回答时主动停止不扣。教师暂停、维护或故障造成的终止不冒充学生主动停止。 |
| R07 | 跨日仍待审：自动移出待审队列，标记已过期，释放预留额度；问题、附件及审计历史继续保留。这是用户对“自动删除”的最终澄清，不物理删除历史。 |
| R08 | 教师可给单个学生或选中的多个学生调整今天的可用次数；有全选全班操作。以“+1、-1、自定义增减”为主，记录操作者、时间和原因。 |
| R09 | 批量导入学生账号和初始密码，强制首次登录改密；忘记密码由教师重置，重置后再次强制改密。暂不要求学号规则或学校统一身份系统。 |
| R10 | 支持图片及用于 Python 教学的文本类附件；能够审核图片内容和文本文件全文。只带文件或图片的提问也必须审批；上传本身只是本地准备，不单独扣次或调用模型。 |
| R11 | 教师机始终联网；依赖仍随便携包提供，不要求本地离线模型。上游必须具备所启用的图像输入能力。 |
| R12 | 已提交问题、审批、调整记录、对话和相关附件永久保留，教师可以导出学生对话。学生不能通过删除聊天或临时会话使教师留存记录消失。 |

### 本期采用的具体默认值

这些是满足上述规则的实施默认值，不是待用户再次回答的问题：

- 一个学生同一时刻最多一个活动请求，包括待审、已批准排队和生成中；换浏览器也不能增加。
- 待审默认一直保留到当日结束；取消旧 Filter 的固定一小时业务过期规则。传输连接超时与业务过期是两回事。
- 上游并发初始为 4，可由教师设置为 1—8；30 人可以同时提交，实际生成按批准顺序排队。
- 连接超时 10 秒，首个可展示输出超时 60 秒，单次生成最长 300 秒；均作为可调整的运行配置。
- 全班暂停阻止新提交和新派发；已经生成中的请求默认继续。另设教师“停止生成”操作，按意外/管理中断处理，不扣学生次数。
- 每个学生可以单独暂停 AI 权限。调整次数不会自动解除暂停。
- 原生自动标题、标签、追问建议、自动补全、上下文 AI 摘要、自动搜索、工具调用、代码执行、语音、图像生成和多模型并行不纳入首版。Python 文件只作为教学材料传给模型，不在教师机执行。
- 教师可以设置课堂提示词和允许的模型；学生不能自由改系统提示词、接入自有提供商或启用额外插件。
- 教师测试默认免审批、免学生额度，仍走相同的唯一模型出口并记录为教师测试。
- 本期默认日额度固定为 3；单人/批量调整仅影响今天。没有直接清零使用历史的按钮，“补回机会”通过带审计的正向调整完成。
- 历史永久保留不等于无限制上传：实施附件大小限制、磁盘容量提示和备份，不自动删除已提交历史。

### A2. 现有流程

1. CMD 调用 PowerShell，使用相对路径启动便携 Python。
2. Open WebUI 监听 `0.0.0.0:3000`，审批服务监听 `127.0.0.1:8790`。
3. bootstrap 登录保存的教师账号，再通过 Open WebUI Functions API 安装、启用并设为全局 Filter。
4. 普通聊天入口验证 Open WebUI 登录身份，将数据库 UserModel 作为 `__user__` 传入 Filter。
5. Filter 取最后一条用户消息的文字，向审批服务 POST，请求标识为用户、会话和消息 ID 的拼接。
6. 审批服务在 SQLite 中保存 pending；教师可批准、修改后批准或拒绝。
7. Filter 每秒轮询；批准后原 Open WebUI 任务继续调用上游。审批服务本身不生成回答。
8. 拒绝或一小时超时在 Filter 中抛异常。数据库没有取消、过期、派发或完成状态。

Open WebUI 的“message_id”在普通界面生成路径中通常是回答消息 ID；另有“user_message_id”。实施者不得混用二者，否则重生成、重复点击和分支聊天的幂等关系会错误。

- 保留现有成功设计：参数化 SQL、不可由学生关闭的全局 Filter、审批条件更新；双教师/双标签同时决定同一记录时第二次返回 409，不能误报为决策覆盖漏洞。
- 未对干净 Windows 电脑、30 人压力或真实模型做完整验收；不要把依赖检查通过写成上述测试已通过。

## C. 推荐改造架构与完整生命周期

### C1. 方案选择

| 方案 | 评价 |
|---|---|
| 继续只修原 Filter | 改动小，但无法覆盖直连路由和审批前副调用；也不掌握模型执行结果。不能满足本任务。 |
| 把现有上游连接换成审批代理 | 能集中上游出口，但需要额外可靠地注入身份、操作 ID，并约束所有副调用。可行但适配面较隐蔽。 |
| 官方 Pipe 作为课堂模型，独立服务拥有唯一真实上游出口 | 推荐。Pipe 接收可信用户和完整模型输入；服务统一负责审核、执行、计数和留存。原生账号/聊天仍保留。 |

本期采用第三种。它不是深度分叉 Open WebUI：优先使用原生 Functions、文件和用户 API；课堂登录约束、API 防护和状态页面通过独立适配模块接入当前启动器。若原生前端没有可用扩展位置，允许一份针对准确版本的最小源码补丁，范围仅为首次改密跳转、课堂状态/操作标识、附件上传及停止事件。禁止修改压缩后的 JS 字符串、维护无边界 monkey patch 或顺带重写 Open WebUI。

### C2. 组件职责

~~~mermaid
flowchart LR
    U[学生浏览器] --> W[Open WebUI<br/>账号与聊天]
    W --> G[课堂认证与请求适配层]
    G --> P[官方 Classroom Pipe]
    P --> S[课堂服务<br/>审批、额度、执行、归档]
    T[教师同源管理页] --> G
    G --> S
    S --> DB[(SQLite)]
    S --> F[(附件与回答归档)]
    S --> AI[教师配置的真实上游]
    AI --> S
    S --> P
    P --> W
~~~

1. Open WebUI 保留学生聊天体验、账号密码哈希、角色和已有聊天。
2. 课堂 Pipe 是学生唯一允许选择的模型入口，可以在服务端映射一个或多个教师允许的模型，但一次只调用一个。
3. 真实提供商密钥只由课堂服务持有，不再留在学生可达的 Open WebUI 普通 OpenAI/Ollama 提供商配置中。清理前先迁移和验证，避免丢失原配置。
4. 原 Filter 改为轻量附件准备/状态适配，不再独立收费、长期等待或持有第二套批准状态。
5. 课堂服务为唯一审批、额度及最终模型输入/输出的事实源。即使学生绕开界面直接请求 API，也只能被拒绝或经过同一事实源。
6. 3000 提供同源 `/classroom/*` 页面和 `/api/classroom/*` 桥接 API。8790 只保留内部服务端口并强制认证，匿名原审核页和匿名决策接口移除。
7. 单实例服务 + 本地 SQLite 足够作为本班初始架构；不为本期引入 Redis/PostgreSQL 集群。JWT 撤销按 H 节适配，不假装原生无 Redis 已解决。

教师仍具完整管理员权限，可以改模型、导入学生、调整次数和导出数据。若教师人为修改安全配置，课堂自检应报告不满足保护条件并暂停学生调用；这不是限制教师管理权限。

### C3. 请求提交与批准绑定

每次明确发起的新问题：

1. 前端创建一个操作 UUID，作为重传幂等键持久在当前操作中；刷新重试沿用。它只是幂等标识，不是授权凭证。
2. 适配层验证原生用户、课堂会话、enrollment、首次改密状态及聊天/文件所有权。不能接受 body.user_id、姓名、IP 或 role 字段作为身份。
3. 只允许课堂 Pipe 模型。删除或拒绝学生输入中的内部上下文、服务身份、批准状态、工具、任意上游 URL 等控制字段。
4. 文件在本地校验并生成不可变快照；组装最终模型、系统提示词、有效历史、当前文字、附件以及允许的生成参数。不得先调用 AI 来解析或摘要。
5. 在服务端生成 request_id。计算规范化的输入指纹：绑定 user_id、操作键、会话/分支、模型与配置版本、完整实际上下文和附件内容哈希。
6. 同一用户同一操作键、同一内容：返回既有请求；不同内容：409；学生另外生成操作键也仍受额度和活动请求限制。
7. 在一个 SQLite 写事务内惰性建立当日额度桶，校验剩余和全班/学生状态，预留一次，写入 pending 请求和审计。
8. 学生显示“待教师审核”“可用/预留次数”，教师看到最新文字、图片、文本附件、模型和可展开的完整有效上下文。
9. 教师决定必须携带 expected_version；事务中重新判断是否跨日、是否已终结及相关权限。
10. 批准记录具体快照版本与 digest。修改后批准生成新的 effective 快照，并绑定该版本；保留原问题。教师若需要移除附件，必须在 UI 明确操作并产生新快照，不能因改文字而意外丢附件。
11. 从批准到发送不能重新加载可能变化的附件、模型配置或系统提示词。派发前再次校验授权、暂停状态及快照。配置变化使待执行批准失效时退回待审并提示，不能静默换模型。
12. 上游工作进程只领取一次执行权，只发送已保存的 effective payload。禁止批准后由另一个调用者携带新 body 替换。

可信请求上下文必须隔离到具体操作，不能放进共享 Filter/Pipe 实例的可变属性。当前 Open WebUI 某些路径会复用 request/state 和插件实例；使用明确的不可变操作上下文、服务端覆盖的关联值或任务隔离机制，避免并发学生串号。来自 metadata 的 task、user_id、request_id 不因参数名看起来“内部”就自动可信。

### C4. 状态与额度结算

使用“预留”和“正式使用”分开记录。提交会降低界面可用次数，但只有最终收费状态才增加 used。

| 状态/事件 | 预留 | 本请求正式使用次数 | 上游调用 |
|---|---:|---:|---|
| 校验失败、无额度、暂停、未改密 | 0 | 0 | 0 |
| pending | 1 | 0 | 0 |
| rejected（教师拒绝） | 0 | 1 | 0 |
| approved_queued | 1 | 0 | 尚未调用 |
| generating | 1 | 0 | 最多 1 次派发 |
| completed | 0 | 1 | 已正常结束 |
| cancelled_before_output | 0 | 0 | 未发送或没有可展示输出 |
| stopped_by_student_after_output | 0 | 1 | 已有可展示回答，学生主动停止 |
| interrupted | 0 | 0 | 已有输出也不扣；标记故障来源 |
| expired | 0 | 0 | 不得发送 |
| interrupted_unknown | 0 | 0 | 无法确认故障前上游执行结果；不得自动重发 |

“已有回答”依据服务端已经持久化并交付到有效聊天订阅的可展示正文事件，不能把 HTTP 200、心跳、provider usage 或隐藏思考字段当作回答。停止请求记录学生主动动作及最后接收序号；这类接收声明只能影响计数分类，不能给予新调用权。不能只信任客户端声明“网络错误”而退款。

同一终态只能结算一次。完成、主动停止、故障、午夜过期同时到达时，通过状态版本和事务产生唯一结果。任何重复事件都返回已确定状态，不新增 ledger。

待审在当日最后一个瞬间之后不再能被批准或拒绝收费：教师点击时必须先执行到期检查。后台清理定时器只是辅助，不能是唯一保证。

已批准排队或生成中的请求跨日继续归属于提交时的日额度；用户要求清理的是“仍待审”请求。第二天新额度按新日桶产生，但“每人一个活动请求”仍跨日生效。不要把跨日完成扣到第二天。

### C5. 重试、断网、刷新与重启

- 浏览器刷新/暂离本身不是学生主动取消，也不必然表示生成失败。若后台完成且结果可恢复，按成功一次处理；如果底层确实中断，按 interrupted 零次处理。
- 页面恢复先按 request_id 查询状态并重放已经持久化的回答事件，不能再次发送上游 POST。
- 学生主动点停止先调用课堂 cancel/stop API；由服务停止上游并结算，再取消 Open WebUI 消费任务。绕过该 API 调用原生 task stop 时，适配层也必须关联到同一 request_id，不能遗漏或误判成网络故障。
- 断线检测/消费租约过期使任务确实终止时，由服务记录故障，释放预留，归档部分回答并标记“不完整”。
- 课堂服务重启：pending 同日可恢复，过期则终结；已批准但确知尚未派发的可重新排队；generating 或派发结果不明的记 interrupted_unknown、释放预留，不自动重发。
- 原生 WebUI 重启：通过关联心跳和实例标识使执行任务停止/确认状态；挂起操作可查询恢复，不能用新 message_id 重新获得旧批准。UI 记录恢复不应重新调用 AI。
- “重试相同操作”指请求状态重取/响应重放。已终结失败后的“重新提问”明确创建新操作并重新审核；失败的旧操作仍为零使用。界面不能在用户不知情时自动新建。
- 即使服务在“写派发标记”和“发出 HTTP”之间崩溃，也不能宣称外部调用 exactly-once。保守标记结果不明、零扣费、无自动重发；上游实际费用可能已产生，与课堂次数分开。
- 上游支持幂等键时可额外传递 request_id，但不能假设所有 OpenAI 兼容提供商都支持。
- 每人活动请求上限、全局并发和提交速率限制用于减轻反复取消/故障占用，不得通过偷偷扣次数替代用户的零扣费规则。

### C6. 时区、日界和人工调整

- Windows 上优先用已打包 tzlocal 取得教师机 IANA 时区，使用 zoneinfo + tzdata 计算自然日边界；不能只保存固定 UTC+8 偏移。
- 全部事件保存 UTC 时间，同时日桶保存 quota_date、当时的 timezone_id 和配置版本。过期时间是下一个当地自然日零点换算的 UTC 时刻，不是简单加 24 小时。
- 服务重启读取教师机时区，检测变化并记录系统审计；历史日桶不重算。相同 user_id + 日期复用同一日桶，不因为时区版本变化再发一份额度。
- 时区无法识别或系统时钟异常倒退导致业务日期不可信时，暂停新扣留/派发，显示可操作错误；不得偷偷按学生时区或 UTC 建桶。
- 日桶字段：base_limit、adjustment、used、reserved；`available = base_limit + adjustment - used - reserved`。
- 第一次在某日观察到请求时即可创建该日桶，不依赖午夜必须开机；服务次日才启动时，恢复事务先终结所有过期待审，再允许新提交。禁止“进程启动就重新发 3 次”。
- +1/-1 增减 adjustment，不能直接改 used 或删除 ledger。减少后 available 不能小于 0，不能取消已经预留的请求。
- 批量默认全有或全无：先预览全部选中学生的前后次数，提交时一个事务重新校验版本。任一学生不合法则整批 409/422，明确说明，没有悄悄部分成功。
- 每次调整带独立幂等键、教师 ID、原因及每人前后值。默认原因可为“课堂临时调整”，教师可改。
- 不做复杂长期套餐和班级共享额度。以后如果支持默认日额度修改，应对未来日桶生效，另立需求。

## D. 数据与文件模型

原则：Open WebUI 继续拥有原生 auth/user/chat 表；课堂服务使用自身数据库及迁移。不要往第三方 user 表随意加 quota 字段，不直接写原生密码哈希。下面是逻辑模型，可合并物理表，但字段语义、约束和事务边界不能丢失。

### D1. classroom_settings / schema_migrations

| 字段 | 用途 |
|---|---|
| key、value_json、version、updated_at、updated_by | 单班配置及审计关联，包括暂停、并发、超时、模型清单和附件限制。 |
| detected_timezone、timezone_revision | 教师机当前时区与变更版本；不是学生配置。 |
| schema_version、migration_checksum、applied_at | 自有数据库迁移记录，可验证版本与脚本一致。 |

提供商 API Key 等秘密不放入可导出的 settings 表；另用本机受限凭据文件/Windows DPAPI 保存。迁移到新电脑必须有明确重新输入密钥的流程，不能只复制 DPAPI 密文宣称可用。

### D2. students

| 字段 | 用途 |
|---|---|
| user_id（PK） | 原生不可变 Open WebUI 用户 ID；额度归属的唯一依据。 |
| roster_name、login_identifier | 教师管理的显示姓名和实际 email 登录标识，脱离可编辑昵称。 |
| default_daily_limit | 本期统一初始化为 3，保留扩展能力但不提供长期额度 UI。 |
| ai_enabled | 单人暂停开关。 |
| enrollment_state | provisioning、active、disabled、deleted_origin；缺登记的普通账号不能调用课堂模型。 |
| created_at、updated_at | 名册建立与修改时间。 |

原生账号删除后保留此记录为归档身份，不级联删除历史。新账号即使邮箱相同也不能自动继承旧用户 ID。

### D3. security_states / classroom_sessions

| 字段 | 用途 |
|---|---|
| security_states.user_id（PK） | 教师和学生均可有安全状态。角色仍以原生实时校验为准。 |
| must_change_password | 首次导入和管理员重置后的必改标记。 |
| credential_operation_state | ready、initializing、reset_in_progress、reset_failed；非 ready 状态默认禁止学生使用。 |
| auth_epoch | 每次改密、重置、注销全部会话增加；使旧课堂会话失效。 |
| password_changed_at、reset_by、updated_at | 安全操作记录，不存密码。 |
| sessions.token_fingerprint（PK）、user_id、epoch | 原生登录令牌的 SHA256 指纹，登记其所属安全代次；不存原始令牌。 |
| issued_at、expires_at、revoked_at、last_seen_at | 短期课堂会话有效期与撤销/清理。 |

只在服务端确认原生密码登录成功之后登记会话；不能在第一次见到任意有效旧 JWT 时自动登记。默认课堂学生会话最长 12 小时且不超过原生 JWT 过期时间；教师可调。临时初始会话只有改密能力。详细安全顺序见 H3。

### D4. daily_quotas

| 字段 | 用途 |
|---|---|
| user_id、quota_date（联合 PK） | 每学生每自然日唯一日桶；不把 timezone_revision 放入主键制造双份额度。 |
| timezone_id、timezone_revision | 创建日桶时的教师时区快照。 |
| base_limit、adjustment | 当日基础额度快照及教师增减总和。 |
| used、reserved | 正式使用量和活动请求预留量。 |
| version、created_at、updated_at | 并发校验与诊断。 |

非负校验：used >= 0、reserved >= 0、base_limit + adjustment >= used + reserved。本期单活动请求下每人的 reserved 最大为 1。日桶可由 ledger 重算核对，数据库事务不能只更新其中一边。

### D5. review_requests

| 字段 | 用途 |
|---|---|
| id（UUID PK）、user_id | 服务端请求及可信归属。 |
| client_operation_id、client_payload_digest | 重传关联及防止同键替换请求；唯一约束为 user_id + operation_id。 |
| chat_id、user_message_id、assistant_message_id、parent_request_id | 原生聊天、两类消息和分支关系，正确恢复/导出/构建上下文。 |
| quota_date、timezone_id | 固定归属日桶。 |
| status、version | C4 状态与乐观并发控制。 |
| original_snapshot_ref、effective_snapshot_ref、effective_digest | 原始和实际批准模型输入的不可变归档引用及哈希。 |
| provider_profile_id、provider_profile_version、model_id | 本次批准使用的具体上游配置版本；不含密钥。 |
| submitted_at、expires_at、decided_at、started_at、finished_at | UTC 生命周期；pending 过期时间为提交日结束。 |
| decision_actor_id、decision_kind、decision_note | 教师的 approve/reject/edit 及原因。 |
| reservation_state、charge_units、charge_reason | 预留 open/released/consumed；终态次数只能 0 或 1，原因可追查。 |
| error_code、interruption_source | 规范化错误和区分学生主动停止、网络、上游、维护、重启。 |
| legacy_id、legacy_status、provenance | 旧记录保留来源，不能把旧 approved 当成新执行授权。 |

为 user_id + 活动状态建立部分唯一索引。为 status/submitted_at/id、user_id/submitted_at/id、pending/expires_at 建索引。按稳定游标分页，不能只使用时间戳导致同秒问题丢失。

### D6. execution_attempts / response_events

| 字段 | 用途 |
|---|---|
| attempts.id、request_id（唯一） | 本期一个已批准操作最多一个对外派发尝试；传输重连不新建 attempt。 |
| worker_instance_id、claim_token、claimed_at、lease_expires_at | 唯一领取和服务重启/失联识别；claim_token 不是学生凭据。 |
| dispatch_state、dispatch_marked_at、first_output_at、ended_at | 分辨未派发、派发结果不明、生成和结束。 |
| upstream_request_id | 提供商返回的关联 ID（若有），不作为授权。 |
| output_ref、finish_reason、termination_source | 已生成的完整或部分可展示输出和结束分类。 |
| response_events.request_id、seq（联合唯一）、event_type、payload_ref、created_at | 可重放的流式事件；按 seq 续订，不向上游重新调用。 |
| delivered_seq、consumer_lease | 判断已交付的正文和消费端失联；不要仅靠客户端自报做授权。 |

避免一个 token 一次 SQLite fsync：有界合并流片段，例如 200 ms/4 KiB 批量持久化，先持久化再对外发出。终态前刷盘并原子结算。归档对象通过临时写入、校验和原子改名发布；磁盘写入失败属于意外中断，不能成功计数但丢回答。

### D7. quota_ledger / teacher_actions

| 字段 | 用途 |
|---|---|
| ledger.id、user_id、quota_date、request_id（可空） | 日桶及相关问题。 |
| kind | reserve、settle_consumed、settle_released、teacher_adjust；退款若用于人工纠错须另记关联事件。 |
| delta_reserved、delta_used、delta_adjustment | 可重放计算的有符号整数。 |
| actor_id、reason、created_at、operation_key | 人工或系统来源、幂等与审计。 |
| batch_id、before_json、after_json | 批量操作关联和前后结果。 |
| teacher_actions.id、actor_id、action、target_ids、result、created_at | 审批、暂停、重置、导入、导出等通用审计。 |

每个 request_id 只能有一个最终结算 ledger，使用唯一约束而不是仅靠 Python if。教师调整幂等键按教师 + 操作类型绑定规范化请求体；同键异体返回冲突。

### D8. attachments / snapshots

| 字段 | 用途 |
|---|---|
| attachment_id、owner_user_id、request_id、source_file_id | 不可变附件、原生文件来源和归属。 |
| original_filename、media_type、size_bytes、sha256 | 展示与校验；文件名不是存储路径。 |
| blob_ref、normalized_ref、text_encoding | 私有原始文件、规范化用于模型的内容及文本编码。 |
| image_width、image_height、preview_ref | 图像解码限制和教师预览。 |
| created_at、retention_class | 已提交永久归档和未提交临时上传区分。 |
| snapshot_ref、schema_version、sha256、created_at | 原始/有效上下文与输入的规范化版本。 |

实际文件在 data/classroom/blobs 下按随机 ID 或内容哈希组织，不接受客户端绝对路径；所有下载经过身份/所有权校验。正文与附件永久保留，不能仅保存会失效的 URL。未提交临时上传可在 7 天后清理，但不能清理任何已引用对象。

### D9. account_imports / import_rows / exports

| 字段 | 用途 |
|---|---|
| imports.id、teacher_id、source_digest、created_at、status、summary | 导入批次、来源指纹及结果，不保存原始带密码 CSV。 |
| rows.batch_id、row_number、normalized_login、roster_name、status、user_id、error_code | 逐行幂等与恢复；无 password 字段。 |
| exports.id、teacher_id、filter_json、format_version、status、file_ref、sha256、created_at | 导出可追踪、可校验、不重复生成。 |

导入预览中的初始密码只短暂存在于受限内存；教师确认后执行，完成/超时销毁。需要重试时重新提供源文件或让教师重置，不能为方便恢复而存长期明文。导出的初始密码清单是用户明确请求的敏感一次性交付，和普通历史导出严格分开。

### D10. 事务与一致性要求

- SQLite 使用本地磁盘、WAL、busy_timeout、foreign_keys，关键写事务 BEGIN IMMEDIATE；每个事务持有时间短。
- 禁止持有数据库写锁等待 HTTP、教师决定、文件解析、密码哈希或上游生成。
- 预留、请求创建、ledger 一起提交；决策、终态结算、ledger 一起提交；批量调整同理。
- 文件对象可先写入准备区，再在事务中发布引用；故障产生的未引用准备对象可以回收，不能反向删除正式归档。
- 两个独立数据库没有分布式事务。账号导入/重置用 provisioning/operation 状态及幂等补偿恢复，不通过假设“两个 API 都会成功”实现。
- 单实例排他锁和实例 ID 防止重复启动两个消费器；数据库约束仍作为最终防线。
- 上线前核对 daily_quotas 与 ledger 聚合完全一致；有差异时暂停新执行，提供诊断，不静默清零。

## E. API 规格与身份边界

所有外部课堂 API 位于 Open WebUI 同源 `/api/classroom/v1`，由适配层验证原生用户和课堂会话，再对内部服务签名调用。不要让学生浏览器直接持有服务令牌访问 8790。

### E1. 通用约定

- JSON 请求只接受 application/json 和对象；未知关键控制字段拒绝。附件使用专门 multipart 入口。
- Cookie 会话的写请求校验 CSRF 与 Origin；Authorization 模式也需明确定义跨源策略。内部端口没有“因为 localhost 所以匿名”的例外。
- 非查询操作支持 Idempotency-Key；修改既有状态携带 expected_version。服务重新验证真实权限和归属。
- 错误统一为 `{"error":{"code":"QUOTA_EXHAUSTED","message":"今日可用次数不足","request_id":"...","retryable":false}}`，无堆栈、密钥和原始内部响应。
- 401 未登录/会话撤销；403 权限或课堂暂停；409 幂等、版本、已决策或过期冲突；413 过大；422 内容/附件/无额度校验失败；428 必须先改密；429 速率限制；503 保护组件未就绪。
- 无额度统一使用 422 + QUOTA_EXHAUSTED，与请求速率 429 区分。前端不得只按状态码猜原因。
- 查询支持 cursor/limit，默认 50、最大 100；时间返回 UTC 与 quota_date、timezone，界面在教师/课堂指定时区展示。
- 每次请求上限、分页和 ID 数量有明确校验；单班批量最多处理当前 30 名 enrolled 学生，不允许角色 admin 混入学生额度调整。

### E2. 学生接口

| 方法/路径 | 用途与校验 |
|---|---|
| GET /me | 返回原生可信 ID、名册名、首次改密状态、课堂暂停及当日额度；不返回秘密。 |
| POST /account/change-initial-password | 验证当前初始密码、新密码不同且满足规则；调用原生改密后完成安全状态并要求重新登录。 |
| GET /requests?scope=mine | 本人问题历史、状态、计数及关联聊天。忽略/拒绝学生传入别人的 user_id。 |
| GET /requests/{id} | 本人问题详情、原始/有效文字、附件引用、处理说明。 |
| GET /requests/{id}/events?after_seq=N | 以本人身份订阅持久事件，可恢复回答。 |
| POST /requests/{id}/cancel | 主动取消/停止；关联到实际执行状态，按 R06 结算。 |
| POST /attachments | 受限图片/文本上传及验证；不执行 RAG 或文件内代码。 |
| GET /attachments/{id}/content | 本人附件或当前请求授权文件，禁止越权和任意本地路径。 |

`/me` 示例：

~~~json
{
  "user": {"id": "owui-user-id", "roster_name": "示例学生", "login": "student01@classroom.local"},
  "must_change_password": false,
  "classroom_paused": false,
  "quota": {
    "date": "2026-09-08",
    "timezone": "Asia/Shanghai",
    "base": 3,
    "adjustment": 1,
    "used": 1,
    "reserved": 1,
    "available": 2,
    "version": 7
  },
  "active_request": {"id": "request-id", "status": "pending"}
}
~~~

正式问题通过原生聊天 API → 适配层 → Pipe → 内部 requests 提交。不要再造一个允许浏览器自填可信身份、批准状态或提供商密钥的直接生成接口。

### E3. 教师接口

| 方法/路径 | 用途与请求 |
|---|---|
| GET /admin/students | 名册、今日 used/reserved/available、暂停和首次改密状态。 |
| PATCH /admin/students/{id} | 修改名册名、ai_enabled；不把普通用户自改昵称同步为名册身份。 |
| GET /admin/requests | 按状态、学生、日期查询全部问题，pending 按提交时间及 ID 排序。 |
| POST /admin/requests/{id}/decision | `decision: approve/reject/edit`，expected_version，note，修改文字及明确附件操作；决定完整快照。 |
| POST /admin/requests/bulk-decision | 教师明确选中记录批量通过/拒绝；每条带版本并返回结果。审批批量允许逐条冲突报告，不把整批错误地重复扣费；与额度批量的原子规则区分。 |
| POST /admin/quotas/preview | user_ids、delta、date，显示前后值及不可执行原因，不产生调整。 |
| POST /admin/quotas/adjust | user_ids、delta、date、reason、expected_versions；整批事务，教师本人由会话取得。 |
| PUT /admin/classroom/state | paused、reason；启停课堂，记录审计。 |
| POST /admin/requests/{id}/stop | 教师中止执行，按管理中断零扣费，不模拟学生动作。 |
| POST /admin/accounts/import/preview | 解析受限 CSV，检查冲突与角色，返回无密码的逐行预览和短期批次凭证。 |
| POST /admin/accounts/import/{id}/commit | 提交对应已预览批次；只建 user/pending 过渡账号，执行首次改密协议。 |
| GET /admin/accounts/import/{id} | 显示逐行结果、错误和待恢复状态。 |
| POST /admin/students/{id}/reset-password | 临时新密码或生成策略；封锁会话后调用原生管理员重置，要求学生再改。 |
| GET /admin/students/{id}/conversations | 原生 API 与课堂归档组合查询，标明来源、分支和完整性。 |
| POST /admin/exports | 学生 ID 集合、日期、是否带附件；生成教师下载 ZIP。 |
| GET /admin/exports/{id} | 进度及授权下载路径。 |
| GET /admin/audit | 决策、额度、导入、重置、导出、暂停历史。 |
| GET /admin/health | 审批链、身份层、队列、磁盘、数据库、备份状态，不输出上游密钥。 |

额度提交示例：

~~~json
{
  "user_ids": ["owui-user-a", "owui-user-b"],
  "date": "2026-09-08",
  "delta": 1,
  "reason": "课堂练习增加一次",
  "expected_versions": {"owui-user-a": 4, "owui-user-b": 6}
}
~~~

响应包含 batch_id、applied、所有学生 before/after 和审计 ID。同一 Idempotency-Key 再次提交相同内容返回原结果；不同内容 409；跨日提交旧预览不静默操作新日桶。

### E4. 内部服务 API

内部前缀 `/internal/v1`，只监听 127.0.0.1 并强制服务认证：

| 方法/路径 | 用途 |
|---|---|
| POST /requests | 可信适配层提交已验证身份、操作、附件和完整快照；完成额度预留。 |
| GET /requests/{id}/events | Pipe 获取状态/回答事件，支持 seq；不能改变批准内容。 |
| POST /requests/{id}/consumer-heartbeat | 消费实例、关联会话与租约，识别 WebUI 重启。 |
| POST /requests/{id}/stop | 适配层提交经过验证的取消来源与用户动作。 |
| POST /identities/session-issued | 原生成功登录事件登记会话指纹及安全版本；防止伪造重放。 |
| POST /identities/security-operation | 导入、首次改密、重置、安全状态迁移的幂等记录。 |
| GET /readiness | 供启动器检查；包含协议版本、实例 ID 和保护状态。 |

服务认证采用安装实例独有密钥生成 HMAC：覆盖方法、路径、正文哈希、时间戳、nonce 和经过验证的 principal；短时间窗并防重放。学生提供的同名 HTTP 头必须删除并由服务端重新构造。密钥不能出现在浏览器、Filter UserValves、日志或导出中；不能接受“签名有效但主体随学生 body 任意填写”。

worker 领取和完成属于同一服务内部函数，不开放给学生或教师直接 POST /complete 扣费。若实现为内部 API，也必须绑定 attempt claim_token 与唯一快照，不接受客户端自报成功。

### E5. 对现有入口的调整

- `/api/requests` 和旧 `/api/requests/{id}/decision`：取消匿名行为；迁移为内部协议或返回受控迁移错误。不能留下兼容匿名后门。
- `/api/chat/completions`、`/api/v1/chat/completions`：完整认证、单模型、操作键和 Pipe 白名单；兼容入口不能绕过。
- `/openai/*`、`/ollama/*`、Anthropic messages、embeddings、音频、图像、tasks、自动摘要、工具/自动化相关入口：按实际路由清单拒绝学生不需要的生成能力。错误返回本地，不尝试上游。
- 原生 functions/models/configs 管理入口继续只允许教师；普通用户工具、插件及提供商设置不开放。
- 原生登录、改密、管理员重置接口必须接入会话登记/撤销流程；不能只保护自建账号页。
- 原生 task stop 与 WebSocket：同样绑定课堂安全会话和真实停止来源；REST 已拦截但 WebSocket 未处理不算完成。
- 健康检查不能是防护豁免生成通道。升级新增路由默认关闭其学生模型能力，直到兼容矩阵验证。

## F. 教师界面

教师通过 Open WebUI 管理员身份访问同源课堂管理页。首页显示三个主要区域：待审核、学生额度、历史/导出。

### F1. 审核队列

- 每条显示名册名、登录标识、提交时间、等待时间、当前模型、附件数量及预留状态。
- 当前文字直接展示；图片缩略图可放大查看实际送模版本；文本文件可看全文和行号，可下载原件。
- 可展开完整上下文和教师改写前后差异；教师批准的是这份有效快照。
- 单条通过、修改后通过、拒绝；拒绝原因可填，界面明确“拒绝也使用 1 次”。
- 复选框、全选当前待审、批量通过/拒绝；显示选中人数及扣次影响，不默认选中全部。
- 取消对话框真正取消；按钮提交中禁用；网络不明时先查原操作结果，不立刻重发新的决定。
- 过期项自动从待审移除，在历史可查“跨日过期，0 次”。显示教师时区。
- 教师修改问题不另建一个收费请求；学生会看到教师修改提示。

### F2. 学生额度

每行：姓名、登录标识、默认 3、今日增减、已使用、预留、可用、暂停状态。

- 单人 +1/-1；选择多个或全班后 +1/-1/自定义增减。
- 操作前预览每人的变化，提交后展示明确结果和历史入口。
- 减次数不能使已预留问题消失或把可用变负。
- 重置密码、单人暂停放在学生操作菜单。教师重置密码显示“下次登录需改密，旧会话已撤销”且后端真实执行。
- 不提供清空历史或伪造已使用次数的“快捷重置”。

### F3. 历史与导出

- 学生、日期、状态过滤；展示原文、教师有效改写、图片/代码附件、完整或中断回答、结算原因、调整与审批人。
- 教师可以导出单人、多人和全班；默认 ZIP 内含 JSON（机器可读）、Markdown（教师阅读）、额度/审计 CSV、附件及 manifest 校验清单。
- 使用稳定学生 ID 和安全文件名，避免同名覆盖、路径穿越、CSV 公式执行和 HTML/Markdown 主动脚本。
- 优先通过原生管理员 API 读取旧聊天；新请求使用课堂不可变归档补足删改、拒绝、过期和中断记录。
- 导出不包含密码、会话令牌、提供商 Key、服务签名密钥或敏感配置。只导出可展示模型输出，不把内部诊断/隐藏推理当课堂回答。
- 永久留存下 UI 必须分页/流式导出，不能永远依赖一次性 /chats/all/db 读全部进内存。

## G. 学生界面与附件策略

### G1. 登录、次数、状态和恢复

- 成功使用初始密码登录后立即进入首次改密页面；改密完成前不能聊天、上传文件或调用其他受保护功能。
- 输入框附近持续显示“今日可用 N 次 / 预留 M 次”；拒绝也扣次的规则在首次使用和提交状态中明确可见。
- 显示待审、批准排队、生成、拒绝、过期和意外中断；不能只显示永久旋转图标。
- 有待审取消和生成停止；点击停止时根据是否已有回答明确其扣次影响。
- 请求去重、限额与必改密均在后端执行。禁用按钮只是辅助。
- 失败/拒绝可编辑后重新提交；这是新操作，重新审批。失败的旧操作不扣；拒绝的旧操作已扣且不自动恢复。
- 刷新后恢复活动请求、已归档回答和 quota；同一个问题不能因刷新生成两次。
- 已经被教师修改的问题须显示原始提问与“教师调整后提交”的版本，后续上下文使用有效版本。
- 禁止学生临时会话、导入任意聊天历史及物理删除服务器留存；可以隐藏/归档自己的会话。若原生删除仍开放，独立课堂归档必须不受影响。

### G2. 图片与文本类附件

本期支持：

| 类型 | 初始限制与处理 |
|---|---|
| 图片 | PNG、JPEG、WebP；每张 <= 5 MiB，解码后 <= 20 百万像素；服务端校验真实格式和尺寸，生成安全预览。 |
| 文本与代码 | .py、.txt、.md、.csv、.json、.yaml、.yml、.log；每份 <= 1 MiB；UTF-8/UTF-8 BOM 优先，失败时可显式选择 GB18030；不静默乱码替换。 |
| 总量 | 每请求最多 5 份附件，总计 <= 10 MiB；文本注入还受模型上下文预算约束。 |
| 暂不支持 | 可执行文件、压缩包、宏、Office、扫描 PDF、音视频、Notebook 执行、外部 URL 文件抓取。拒绝并给出支持格式说明。 |

“文本类文件”在首版指能可靠按文本读取的教学材料。不要因此自动增加 OCR、RAG、Office 转换、任意文件执行等大范围能力。

处理要求：

1. 文件先在本地完成大小、格式、所有权和实际 SHA256 校验；不信任上传元数据里的 file_hash。
2. 原生 `/files/?process=false` 可复用存储，必须由服务端强制这一模式；学生不能改回 process=true 绕到 RAG/嵌入。适配上传与后续状态 UI，避免原生等待永远不会发生的向量化。
3. 源文件复制为课堂不可变附件；教师预览、模型输入和导出引用同一规范化字节版本。原生附件被编辑/删除也不能变更已批准请求。
4. 文本直接在本地提取并带文件名边界注入上下文；不执行 .py，不启用代码解释器，不联网下载模型来读取文本。
5. 图像使用服务保存的实际图像内容传给具备图像能力的上游；纯图片问题也生成待审请求。
6. 禁止任意 file://、网络 URL、localhost URL 与任意磁盘路径输入；已有图片 data URI 也必须解码、限制体积并归档。不得允许用户让后端任意抓取内网资源。
7. 模型不支持图像时在预留/审批前报清楚；不能丢掉图片只传文字，也不能审批后默默换模型。
8. 超过模型上下文时明确拒绝或让学生精简。禁用自动 AI 摘要；如需确定性裁剪历史，应在教师看到的快照中明示裁剪范围，批准后不可再变。
9. 教师文字改写不得把多模态 content 列表整体替换成字符串而丢附件。
10. 本版本插件加载器返回 Filter 实例：`OWUI/utils/plugin.py:298—300`，消费端读取 `function_module.file_handler`：`utils/filter.py:185`。因此不能照抄最新版文档“只设模块级 file_handler”的示例；对当前 0.11.2 实际实例属性行为写集成测试。文件引用被清理前必须保存可信关联供 Pipe 使用，不能清空后让附件消失。
11. 所有自动摘要、历史压缩、搜索、embedding、文件上传处理发生在 Pipe 前的可能路径都纳入 E5 防护清单，不把“用了 Pipe”误认为这些调用已自动覆盖。

### H2. 原生 API 与扩展的优先级

- 使用官方 Pipe / Filter 注册 API，校验 installed content hash、is_active、模型可用性和函数签名。
- 用户创建、改密、角色、文件所有权和旧聊天读取调用原生 API/官方业务处理器，不通过手写 SQL 修改第三方 auth/user/chat。
- 内部 imports 限制在 native_api.py 等版本适配层；对其行为写准确版本契约测试。其他业务代码不散落第三方私有 imports。
- 原生插件不是完整认证中间件。first-password、会话撤销、禁止旁路入口要在 ASGI 适配层或最小明确源码补丁中完成。
- 如果 UI 没有足够的官方扩展点，维护可重放、校验基准哈希的小补丁；修改官方对应 tag 的源码后构建前端。不能把 Sub2API frontend 当成 Open WebUI 前端，也不能直接搜改打包 JS。
- 每个补丁记录 upstream tag、commit/文件哈希、原因、测试和撤销条件。拒绝“任何版本尽量注入成功”；未知版本启动为维护状态。
- 教师管理模型的实际提供商配置移到课堂设置，Open WebUI 只暴露受管 Pipe。旧外部连接在成功迁移后关闭并从普通提供商配置移除真实 Key；用户角色和 API Key 权限不作为唯一隔离手段。
- 禁用原生对学生开放的 workspace tools、direct connections、额外 Functions、API key 建立和不需要的生成特性；E5 的后端约束仍不可省略。

### H3. 首次改密与旧会话撤销

本期不需要 LDAP/SSO，也不因原生 JWT 撤销缺 Redis 而默认增加一整套 Redis 运维。实现独立安全状态和会话登记，覆盖所有公开入口。

#### 原生成功登录

1. 由当前版本原生认证校验 email/password 和账号角色。
2. 适配层只捕获明确成功的服务端登录结果，验证其 user_id，登记返回 JWT 指纹、当前 auth_epoch、有效期。
3. 启用 must_change_password 的学生仅可访问自身会话信息、改密、退出和必要静态资源；不能访问聊天、附件、模型、副接口或建立有权执行的 WebSocket。
4. 普通学生需要 active enrollment + 当前 epoch 的登记会话。未登记的历史 JWT 一律要求重新登录。
5. 所有 API/WS 请求同时通过原生角色检查和课堂安全状态；服务不可用时默认拒绝，不能退回纯原生认证继续用 AI。

可通过当前启动器安装明确的 ASGI 适配或经过测试的原生路由 hook。不得用无限制通用响应改写来捕获任意正文，只处理已锁定的认证端点，并限制缓冲大小。原生登录 UI 也必须进入这条登记流程；另做一个安全登录页却保留不受保护的原生登录不算完成。

#### 批量导入与初始密码

1. 按原生 API 创建 role=pending 的账号作为安全过渡，避免两个数据库写入之间学生已可使用。
2. 建立 students/enrollment 与 security_states，设置 must_change_password=true。
3. 成功后原生角色改为 user，enrollment active。初始密码登录只可改密。
4. 创建成功而第二步失败时维持 pending/provisioning，教师在导入报告中可恢复；不能为了“全部成功”临时放开所有 user。
5. 学生改密必须验证旧密码，新密码不可等于初始/当前密码；经原生改密成功后才更新状态、增加 epoch、撤销旧会话。
6. 完成后要求重新登录，避免同秒 iat 与撤销时间造成边界漏洞；新会话只有成功登录才登记。
7. 改密途中崩溃默认仍为必改/受限状态，通过教师重置恢复。不得在原生改密前先清除强制标志。

#### 教师重置密码

1. 在课堂数据库事务中设 reset_in_progress、must_change_password=true、auth_epoch+1，立即阻断旧会话。
2. 调用原生管理员重置 API。
3. 成功后完成安全状态并保留必改；失败保持安全封锁并向教师提供幂等恢复操作。
4. 捕获原生管理界面直接重置的同等事件，不能只覆盖课堂重置按钮。正常学生改密也应撤销已有会话。
5. 不把原生成功 JWT 的旧签发时间与客户端提供时间简单比较；使用服务端记录的 epoch/令牌指纹。
6. 注册、被删后重建、角色变化、登出、所有会话注销、教师登录也纳入契约测试。
7. 完整权限的教师仍可以维护账号；紧急恢复走本机管理员维护工具，在学生入口关闭时执行并留审计，不暴露远程匿名恢复路由。

### H4. 账号名册导入

输入推荐采用 UTF-8 CSV：

~~~csv
Name,Email,Password,Role
示例学生,student01@classroom.local,示例初始密码,user
~~~

- 必须用标准 CSV 解析器，支持 BOM、引号和逗号；不依赖原生前端的简单 split。
- 接受原生四列；用户另提供 Name,Username,Password 时，预览中显式把简单标识映射为 `username@classroom.local`，显示最终登录账号，禁止静默改变用户已有合法邮箱。
- 没有自动生成姓名/学号的硬规则。批次内重复、系统已有同邮箱、大小写冲突、非法角色、缺列、空密码和非法编码都必须报告。
- 角色固定学生 user；来自文件的 admin 不得按文件执行。原生过渡创建用 pending 是内部安全步骤。
- 已存在账号默认不覆盖姓名/密码；预览显示冲突或明确关联已有 user，关联操作需要教师明确提交，不能顺便重置其他人。
- 导入可以逐行成功，因为原生 API 不是跨所有账号的单事务。必须有逐行持久结果、重复批次恢复和部分失败报告，不声称“全班原子建号”。
- 并行建号初始限制为 2—4，避免密码哈希瞬时占满教师机；30 人无须追求高吞吐。
- 教师可下载一次性账号初始密码清单；不能提供查询当前密码功能。导入文件不进入普通日志、持久导入表或历史导出。
- 原生手动创建的学生也必须通过 enrollment 和初始改密流程才能用课堂模型。教师可在课堂面板“接管已有账号”，不会因原生新增路径遗漏而免改密。
- 禁止公开自助注册；实际数据库中的持久配置也要更新并读取验证，不能只设置同名环境变量。

## I. 便携部署、配置、备份与恢复

### I1. 包装与配置

- 保持 Windows x64、相对目录启动；程序可解压到带中文和空格的普通本地路径。
- 常用入口不依赖系统 Python、Docker、Node、pip 联网、用户 PATH 或原开发 E 盘。
- 当前已有 fastapi、uvicorn、httpx、pydantic、Pillow、tzlocal、tzdata 等依赖，优先复用。升级任何库先检查 Open WebUI 锁定要求，不盲目 pip install -U。
- 运行锁定文件包含准确版本与可获得的安装包哈希；建包在干净阶段安装/复制依赖并检查；不可依赖当前机器碰巧有某个 DLL/模块。
- 配置统一为一个非秘密文件，含数据根目录、端口、时区检测、并发、超时、上传限制和保护版本；密钥另存。
- 内部端口默认 8790，公开 3000；学生/教师同源访问。继续仅向域/专用网络的 LocalSubnet 开放公开端口。
- LAN HTTP 会明文传输认证信息。首版在受控课堂局域网部署，文档明确边界；不得以“本地网络”声称已加密。需要 HTTPS 时提供受信任证书配置，不把未配置 TLS 的承诺写入验收。
- 不信任任意 X-Forwarded-For；没有代理则不设 forwarded_allow_ips='*'。身份与额度不使用 IP。
- 运行数据保存在 data，日志不打印原文/初始密码/Key；完整问题只保存在受保护归档。
- 教师使用说明更新模型设置位置、首次改密、拒绝扣次、过期保留、单独/批量调整、导出和故障处理。

### I2. 启动与关闭

1. 取得实例锁，校验配置、路径、磁盘空间、依赖、版本哈希、端口归属。
2. 准备安装独有密钥；首次管理员在学生入口可访问前创建，关闭公开注册。
3. 完成/验证自有与原生迁移；失败进入维护状态，不能继续启动模型访问。
4. 启动课堂服务和受保护的 Open WebUI，安装 Pipe/Filter/适配层。
5. 真实 readiness 校验：数据库可用、会话防护有效、只有受管模型可用、匿名决策失败、非受管模型出口失败、生成任务可关联、文件处理不执行 RAG。
6. 本地模型连通性测试可以由教师显式启动；普通启动自检使用模拟/非生成检查，不自动消耗上游费用。
7. readiness 成功后开放学生使用，再显示教师/学生地址。双击重复启动只打开已验证的本实例，不把任意 /health=200 的其他程序当本服务。
8. 单个服务崩溃可恢复对应服务；先关闭学生新请求，避免“半启动”永久报端口占用。
9. 停止：暂停新提交/派发，等待短暂排空；超时教师选择停止或后台默认安全终止，将未完成生成记零次故障；持久化、关闭数据库和网络。
10. PID 校验可执行路径、命令行和实例 ID 后才能 Stop-Process。Start/Stop/Status/Backup 统一 DataRoot。
11. 服务每次重启使用新的 worker_instance_id；旧 claim 不可延续成第二次模型调用。

### I3. 备份与长期留存

- 自动备份建议每天第一次成功启动时做一次，另提供教师一键备份。备份本身可以有轮转保留策略，但不能轮转删除唯一的业务历史。
- 备份同时包含 Open WebUI DB、课堂 DB、已引用的上传/附件/回答归档、非秘密配置、迁移/协议版本和文件清单。
- 采用维护暂停 + SQLite Backup API/可靠 checkpoint + 一致文件清单；禁止只拷贝正在写入的 .db 而漏 WAL/附件。
- 两个数据库和文件引用应标注同一 backup_id/维护屏障，验证引用完整。
- 密钥的迁移与恢复单列说明；机器绑定 DPAPI 不能跨机直接用，应在新机重新配置提供商密钥，并轮换实例内部认证密钥。
- Restore 默认恢复到新目录，校验清单、版本、数据库完整性、文件哈希，再切换启动配置。不得在未验证时覆盖唯一原数据。
- 永久图片归档可能远大于聊天文字，30 人也需要磁盘容量显示与低空间暂停上传/派发；不自行删旧聊天“腾空间”。
- 学生退学/账号删除仅停止访问；历史依然按用户确认永久保留。教师导出保留原稳定身份。
- 导出的 ZIP 是阅读/分析交付，不自动当作可恢复全系统备份；两者格式和用途明确区分。

## J. 现有数据迁移

### J1. 迁移前保护

- 记录旧包校验值、版本、当前服务实例、数据库计数、表结构与文件清单；不要在报告中放密码或 Key。
- 暂停学生访问，正常停止旧服务，创建经过恢复验证的完整备份。
- 所有首次迁移在独立副本执行；保留原目录只读作为回滚基线。
- 不把当前使用中的 data、logs、teacher-admin.json 或 .webui_secret_key 装入面向其他电脑的全新发行 ZIP。

### J2. 修正原生迁移基线

当前库由 create_all 构建，不能仅因为表名存在就认定等于 Alembic head。

1. 锁定 Open WebUI 0.11.2 的完整 schema、迁移脚本及基准哈希。
2. 比对当前库与该版本官方迁移生成的干净库：列、索引、外键、唯一性、默认值及历史数据转换。
3. 对副本检查重复邮箱及一致性；不能为了创建索引擅自删除或合并账号。
4. 推荐产生明确的基线修复迁移，补齐已验证缺口；只有结构及必要数据转换完全等价后，才登记正确迁移 revision。
5. 如果无法证明等价，改用官方流程建立新库，再通过受控迁移适配保留原 user_id、聊天与关系；不得重新 signup 后把旧数据硬挂到新随机用户。
6. 精确报告执行了哪些迁移、哪些是已证明无需执行；不能无条件 stamp head，也不能直接启动一串会 CREATE 已有表的历史迁移。
7. 验证登录、创建用户、聊天、文件、Functions、导出后再进入业务迁移。

### J3. 课堂数据

- 导入现有普通用户到 students，保留 user_id；教师管理员保留权限。
- 现有学生首次进入新系统也要求改密；迁移后所有旧课堂会话要求重新登录。
- 旧 review_requests 的原 ID、key、姓名/邮箱快照、原文、教师改写、决定时间和状态原样保存在 legacy 记录或兼容列。
- 旧 approved 不证明模型成功，不转成可重用授权，也不追扣今天次数。
- 旧 pending 没有可靠完整快照和执行关联：保留历史，标记“迁移关闭，需重新提交”，不自动批准/发送、不扣次数。
- 旧普通聊天继续可查看与导出；继续旧聊天时，将完整上下文作为新的教师可审快照，不能把来源未验证的旧内容直接当成已批准上下文。
- 新额度从切换日开始。不得由旧 approved/rejected 记录推断过去的准确使用次数；导出标记 legacy_usage_unknown。
- 旧本地教师明文密码文件和含密码日志在确认不再被启动依赖后，迁移为受限备份或提示教师处理；不在代码任务中未经计划直接删除唯一恢复信息。
- 上游配置复制进新服务凭据存储并测试映射。确认唯一出口生效后关闭原生真实提供商路径，保留可回滚的加密/受限备份。

### J4. 切换与回滚

- 副本验收通过后，使用同一已验证迁移脚本在维护窗口切换；核对用户/聊天/附件/旧审批数量与哈希。
- 保留旧数据与新版数据分别可识别，禁止用旧服务直接打开已升级不可逆的新库。
- 如果新版已发生新对话，回滚不能简单恢复旧备份丢掉新数据；先归档增量并进入维护，采用已验证的降级/数据合并流程。没有兼容降级时明确停留维护，不能假报回滚成功。
- 回滚旧功能也不得重新对学生开放已知无审批旁路。未恢复完整保护前，仅教师维护访问。

## K. 测试与验收矩阵

所有测试先用可观测模拟上游记录“实际 POST 次数、payload hash、调用时间、返回事件”。安全测试以模型出口零调用为断言，不能只检查 HTTP 错误或界面状态。

### K1. 额度与时间

| 用例 | 必须结果 |
|---|---|
| 新学生当日首次查询 | base=3、used=0、reserved=0、available=3；查询不新建多个桶。 |
| 提交第一问 | pending、reserved=1、available=2，上游 0。 |
| 教师拒绝 | used=1、reserved=0、available=2，上游仍 0；重复拒绝不重复扣。 |
| 教师批准并成功 | 最终 used=1，一次派发；从提交到成功不是扣两次。 |
| 同一天三次拒绝 | used=3，第四次不能进入队列，不发上游。 |
| 同一天三次成功 | 同上；追问和重新生成按新问题处理。 |
| 上游报错/网络断开/服务重启 | 有无部分回答都 charge=0，预留释放，部分输出留存“不完整”。 |
| 学生主动停止无正文 | charge=0；已有可展示回答后主动停止 charge=1。 |
| 教师停止/暂停维护中止 | charge=0，不能记学生主动停止。 |
| 跨日 pending | expired、从待审移除、原日预留释放、历史和附件仍在；新日 base=3。 |
| 午夜同时审批/过期 | 若决定发生时已到 expires_at，必须过期而不是拒绝收费或批准执行。 |
| 已批准/生成跨日完成 | 扣原提交日；新日额度不被错误减少。 |
| 修改学生浏览器/资料时区 | 不影响额度日期。 |
| 教师时区变化、DST、时钟回退 | 自然日正确、旧桶不可重复发放、历史不重写；异常有维护提示。 |
| +1、-1、重传 | adjustment 正确，used 不被改，重复操作不再调整。 |
| 批量调整一人冲突或不足 | 整批不应用，明确显示冲突，无部分静默修改。 |
| 服务强杀后恢复 | ledger 与日桶一致；active 唯一约束仍成立。 |

### K2. 审批、身份与绕过

必须覆盖：

- 同一 request_id/operation_id 并发重复提交，相同内容只产生一份预留和一个请求。
- 复用已批准 key 修改文字、模型、历史、图片或文件：409/重新审核，上游未发送替换内容。
- 一个批准同时两个消费者：一次派发；重复事件、重复完成、重复 stop：一次结算。
- 30 个学生各提交一问：30 个独立归属，最多 30 个活动请求，上游同时执行不超过配置。
- 同学生跨设备/多标签 10 次并发：最多一个活动请求。
- 教师双标签同时批准/拒绝，先提交者成功，另一端收到当前状态冲突。
- 匿名/学生访问教师决策、调额、导入、导出、8790 接口：拒绝。
- 伪造 body.user_id/name/role、X-Review-Token、内部签名头、旧签名重放：拒绝。
- 学生修改显示昵称，不改变名册名、user_id 和额度归属。
- 旧 JWT 在首次改密/教师重置/退出后不能访问受保护 REST 和 WebSocket；无 Redis 环境也成立。
- 直接原生登录、原生改密、原生管理员重置与课堂界面具有一致效果。
- 未改初始密码、未 enrollment、pending/disabled 账号不能生成/上传/调用副接口。
- /openai/chat/completions、/ollama、/api/v1/messages、embeddings、tasks/title、tasks/queries、自动摘要、audio/images、工具和直接提供商路径均验证零非授权上游调用。
- 学生在 /api/chat/completions 中伪造多模型、metadata.task、direct、工具参数、filter_ids 不能取消保护。
- 教师关闭 Filter/删除 Pipe/重新加入直接提供商、或升级路由清单变化时，readiness 变为失败并暂停学生模型访问。
- 本机匿名审批、跨源请求、恶意 Origin、错误 HMAC、过期 nonce 都不能成功决策。

### K3. 附件与上下文

- 纯文字、纯图片、文字+图片、纯 .py、文字+.py、混合多个文件均进同一审批队列。
- 教师预览和上游实际 payload 的文字、图片和哈希一致。
- 上传时未调用模型/嵌入/OCR/外部解析服务；更改 process=true 仍不能绕过。
- 批准后修改/删除原生附件、同名替换文件、伪造 file_hash：不能更改已批准输入。
- 学生引用其他学生 file_id、路径穿越、file URL、内网 URL、巨大 data URI：拒绝。
- 超尺寸、伪装扩展名、解压炸弹型图片、SVG/HTML 主动内容、不支持编码：安全错误，不放行。
- .py 只读为文本，不创建子进程执行文件；Python 教学不默认为服务器代码执行授权。
- 修改后批准保留应有的图片和文本附件；后续追问不恢复旧原文。
- 超上下文/不支持图像模型：本地说明，不静默丢附件、不擅自换模型。
- 老聊天、分支、重新生成和被改写问题的上下文指纹稳定，学生不能注入未展示的历史。
- 图片永久归档、教师导出后可离线查看，不仅有过期 URL。

### K4. 账号、界面与导出

- UTF-8 BOM、引号/逗号、空行、重复登录标识、大小写冲突、无表头/缺列、空密码、admin 角色注入、非法文件均有逐行结果。
- 中途断网/服务崩溃后部分导入可恢复，不重复创建、不修改已有账号密码。
- 导入尚未完成安全状态时账号仍受限；必须改密不可被直调 API 绕过。
- 忘记密码教师重置后旧会话立即失效，下一次必须改密。
- 学生看到实时可用/预留状态；拒绝明确扣次；取消对话框不会提交拒绝或调额。
- 刷新/关闭后恢复不重发模型，状态与服务器一致；异常不会无限转圈。
- 单人/全班对话导出包含原文、有效问题、回答、图片/代码、时间、状态和扣次依据；拒绝/过期/故障同样保留。
- 旧原生聊天通过原生管理员 API 导出，不因缺课堂 request_id 而漏掉；重复归档有 provenance，不冒充不同问答。
- 学生隐藏/删除原生聊天不影响教师永久归档；导出不能越过教师授权范围或包含任何密码/Key。
- 同名学生导出不覆盖，CSV 不执行公式，Markdown/HTML 预览无脚本注入。
- 无敏感真实数据的示例名册、示例对话和教程截图可正常使用。

### K5. 部署、故障与升级

- 干净 Windows x64，没有系统 Python/Node/Docker；中文空格路径、换盘解压均能启动。
- 无依赖下载的启动成功；教师机能联网访问上游。完全断网时显示上游不可用并零扣，不宣称仍能回答。
- 单服务失败、端口被其他程序占用、双击重复启动、旧 PID 被复用、自定义 DataRoot、强杀恢复均可预测。
- bootstrap/迁移/Pipe 安装失败时学生模型出口关闭，不能只因为 /health=200 开放。
- 备份在副本恢复后能登录、查看聊天、恢复附件和额度，两个库及 blob 引用一致。
- 低磁盘、归档写失败、SQLite busy/locked、服务间请求超时都不丢已收费回答或重复扣次。
- 停服务/升级没有长时间持有 SQLite 写锁；无无限内存队列或线程增长。
- 当前精确版本回归通过；升级到其他版本要重新生成路由清单、校验 extension/API 契约并跑关键用例，不自动接受未知版本。
- 发行 ZIP 不含真实 data/logs/凭据/初始密码，校验文件匹配，源码构建可重现组件版本。
- 正常课堂 UI 的提交/状态接口，在 30 人并发和本地模拟快速依赖下，目标 p95 < 2 秒；教师决定到事件可见目标 < 2 秒。模型生成耗时单独统计，不用上游速度掩盖本地阻塞。

### 总验收清单

- [ ] 所有学生可用模型能力均不能跳过审批与额度。
- [ ] 教师拒绝扣 1 次；正常成功扣 1 次；意外中断零次；有回答后学生主动停止扣 1 次。
- [ ] 同一操作最多一个预留、一个最终结算、一个对外派发。
- [ ] 教师机时区的日界正确，跨日待审移出队列但保留全部历史。
- [ ] 单人和全班批量调整可用，历史不可被清零。
- [ ] 批量账号强制首次改密、教师重置可用，旧令牌确实失效。
- [ ] 图片与 .py 等文本文件真实可审、实际送模内容一致。
- [ ] 永久对话/附件归档及教师导出可用，学生删改不破坏留存。
- [ ] 30 人并发、服务重启、网络中断、双决策和幂等重试测试通过。
- [ ] 现有用户 ID、旧聊天、附件、审批完整迁移；没有追扣旧记录。
- [ ] 便携包可换盘、中文路径运行，干净机器无额外依赖下载。
