# 课堂 AI 系统需求文档

**文档版本：** 1.1  
**整理日期：** 2026-09-18  
**适用项目：** Open WebUI 0.11.2 + 课堂审核服务 + Windows 便携式整合包（当前测试候选 2.1.8）  
**源码：** https://github.com/DRMus2000/open-classroom-ai

## 1. 项目目标

为一个班级提供受教师管理的 AI 学习环境。学生可以在局域网内登录、提问和上传 Python 学习相关文件；学生问题在发送给模型前须经过课堂审核通道（教师审核、AI 审核或不审核自动放行，由教师配置）。教师负责名册、账号、额度、审核模式、系统提示词、审计提示词和课堂状态管理。

系统只服务一个班级，默认最多 30 名学生和 1 名教师。教师电脑保持联网，学生通过局域网访问教师电脑上的 WebUI。模型可以是教师配置的 OpenAI-compatible HTTPS 服务。

## 2. 已确定的业务规则

### 2.1 角色与规模

- 一个安装实例只对应一个班级，最多 30 名学生。
- 只有 1 名教师管理员；教师拥有审核、学生管理、额度管理、导出、系统配置和账号重置权限。
- 学生不能注册、不能提升权限、不能访问模型提供商连接、不能绕过课堂审核服务。
- 学生账号使用登录标识和密码。名册字段名为 `Name,Email,Password,Role`；当前 Open WebUI 登录接口要求邮箱样式，推荐使用 `姓名拼音@a.b` 或 `学号@a.b`。地址不需要真实收信，但必须唯一并包含合法域名格式。

### 2.2 每日额度

- 每名学生默认每天 3 次 AI 提问。
- 额度按教师端检测到的时区按自然日重置。
- 提交时预留额度；教师拒绝的请求仍扣除 1 次。
- 学生主动停止且已经产生回答时扣除 1 次。
- 网络故障、模型错误、服务重启和其他未产生可靠回答的意外中断不扣除额度。
- 同一个操作 ID 重试是幂等重试，不产生第二次扣次或第二次模型调用。
- 跨日仍在待审核队列的请求移出待审核队列并标记过期，释放预留额度，但保留历史和审计记录。
- 教师可以增加或减少当天剩余额度；调整支持单个学生和批量学生，记录操作者、时间、原因和版本。
- 暂停全班或暂停某个学生时不能提交新的请求；已有状态按状态机继续收敛。

### 2.3 审核流程

审核模式（课堂设置）三选一：

- **teacher（默认）**：进入教师待审核队列，由教师批准或拒绝。
- **ai**：串行调用课堂同一提供商做独立审计（共用审计会话与审计提示词）；通过则入生成队列，拒绝则对学生显示「AI助教未批准这次提问」；上游短暂失败自动重试，仍失败则回退教师待审（不自动扣次）。
- AI 审核与生成任务独立调度；审核读取对话与文本附件全文。含图片、上下文超过 40,000 字符或审核结论不明确时转教师处理；思考过程中的示例不能作为最终审核结论。
- **none**：提交后直接进入生成队列，不经人工/AI 审核。

典型教师审核流程：

```text
学生登录
  → 学生端课堂对话页
  → 身份和请求校验
  → 课堂服务保存原文、附件和额度预留
  → 按审核模式分流（教师队列 / AI 审计 / 直接排队）
  → 仅获准请求进入模型提供商
  → 流式回答保存到课堂服务
  → 学生端按事件增量显示回答并确认送达
```

- 队列显示学生姓名、提问原文、提交时间、状态、审核通道标记和附件入口。
- 教师可以逐条批准、拒绝、停止，也可以批量批准或拒绝。
- 拒绝时可填写原因；学生能看到拒绝状态（区分教师拒绝与 AI 拒绝文案）。
- 教师可以查看原文和附件，也可以在保留原始快照的前提下修改后批准。
- 允许学生继续同一条已完成对话；后续请求从已批准历史恢复上下文。
- 学生不能直接请求 OpenAI、Ollama、Embedding、Retrieval、Tools 或未知模型路由。
- 单条学生/访客提问正文不超过 1000 字（前后端一致校验）。

### 2.4 模型和系统提示词

- 课堂服务统一管理提供商 HTTPS 地址、API Key 和允许的模型 ID。
- API 地址、模型名称支持保存；API Key 使用 Windows 当前用户 DPAPI 加密保存，明文不得写入文件或命令行。
- 当前连接配置支持多个模型 ID，但实际课堂 Pipe 默认使用第一个允许模型；后续可增加模型选择器。
- 默认学生系统提示词为：

  > 你是课堂学习助手。帮助学生理解问题、核对推理并形成自己的答案。

- 教师管理页提供“课堂系统提示词”入口。教师可以修改最多 20,000 字的统一提示词，使用版本号防止并发覆盖。
- 新系统提示词只作用于新对话；已有请求和已有对话使用其原始快照，不被追溯修改。
- 学生不能修改统一系统提示词。教师自己的对话不占学生额度。

## 3. 账号和名册需求

### 3.1 名册格式

CSV 必须是 UTF-8，表头严格为：

```csv
Name,Email,Password,Role
张三,zhangsan@a.b,至少八位密码,user
```

约束：

- 1 至 30 行；`Name` 必填且不超过 120 字。
- `Email` 必须是唯一的邮箱样式登录标识；推荐 `name@a.b`。
- `Password` 至少 8 位，只作为首次登录密码输入，不应写入预览响应或课堂数据库。
- `Role` 只能为 `user`，教师账号不通过学生名册导入。
- 文件可包含中文；无法按 UTF-8 解码时应明确提示另存为 CSV UTF-8。

### 3.2 预览和提交

- “预览导入名册”只预览，不创建账号、不提交导入。
- 预览结果按行显示：行号、姓名、登录账号、角色和中文校验结果。
- 错误代码至少包括：姓名无效、邮箱无效、文件内重复、初始密码过短、角色不允许、账号已存在和原生账号接口失败。
- 全部行无效时，确认按钮禁用，后端拒绝空导入；不得显示“completed/results=[]”这样的假成功。
- 有效行可以导入，错误行跳过，并显示成功、失败和跳过数量。
- 导入过程可安全重试；原生账号创建和课堂名册写入需要避免重复账号。
- 学生首次登录必须修改密码，修改后旧会话失效。
- 教师可重置学生密码；重置后学生必须重新登录并再次修改。

## 4. 学生端产品需求

- 登录后直接进入课堂提问页，不停留在 Open WebUI 原生首页或右下角浮动窗口。
- 页面采用简洁的 AI 对话布局：左侧最近对话，中央消息流，底部输入框；移动窗口时侧栏可收起。
- 空状态使用简短引导，不堆叠大量卡片、设置和统计信息。
- 学生消息和 AI 回复以气泡/消息块形式显示；审核等待、生成中、拒绝、完成等状态在对应消息旁显示。
- 保留历史对话、开启新对话、同一对话连续追问、停止请求和重试幂等请求。
- 支持上传 `.py/.txt/.md/.csv/.json/.yaml/.yml/.log` 及 PNG/JPEG/WebP 图片；最多 5 个文件、总计不超过 10 MiB。上传文件必须经过课堂服务校验。
- AI Markdown 回复正常渲染标题、粗体、斜体、列表、表格、引用、行内代码和代码块；代码支持复制。
- 禁止原始 Markdown 造成脚本执行；HTML 输入关闭，外部图片不直接加载，链接使用安全协议和新窗口。
- 学生能看到今日剩余、已用和预留次数，但不能修改额度、模型或系统提示词。
- 提问输入显示当前字数/1000；生成中按 durable events 增量渲染，避免整包轮询造成的卡顿。

## 5. 教师端产品需求

- 显示课堂服务状态、时区、暂停/恢复全班 AI 和刷新按钮；侧栏分区：审核队列、学生与额度、使用概况、名册导入、课堂设置。
- 审核列表提供状态筛选、分页/加载更多、单条操作和批量操作；在审核页轻量刷新，无变化时不整页重画；批准/拒绝后优先刷新队列。
- 审核列表直接显示学生姓名和本次提问原文，不显示整段上下文 JSON；高级修改 JSON 入口可以折叠保留。
- 学生列表支持每页 10、20、30、50 人，上一页/下一页，当前页全选，跨页保留选择和清空选择。
- 学生列表显示姓名、登录账号、今日额度、已用、预留和当前请求状态。
- 支持启用/暂停学生 AI、改名、重置密码、单个/批量额度调整。
- 名册区提供 CSV 预览/确认导入、单独添加一名学生，以及导出选中学生/全班。
- 提供「课堂系统提示词」与「AI 审计提示词」：读取当前版本、编辑、保存、重新加载、恢复默认；系统提示词只作用于新对话；审计提示词仅用于 AI 审核模式。
- 提供审核模式切换、临时免密访客链接（需 LAN 启动）、AI 审计历史与清空会话。
- 「使用概况」提供今日概览、词云、学生排行与时段分布；词云仅含已通过审核的提问。
- 导出应包含学生对话和可选附件；导出、备份和恢复均需保留审计能力。

## 6. 安全与权限需求

- WebUI 只负责界面和原生会话；课堂服务是唯一的额度、审核、身份和模型出口权威。
- WebUI 到课堂服务使用本机回环地址、HMAC 签名、时间戳、一次性 nonce 和身份指纹。
- 每个请求绑定认证用户、操作 ID、聊天 ID、消息 ID、父请求和附件摘要；禁止客户端伪造身份、批准状态或模型提供商字段。
- 学生请求默认拒绝未知模型能力路由；学生模型请求必须使用受管 Pipe。
- 管理员可以使用管理 API，但学生不能通过修改角色字段取得管理员能力。
- 输入大小、附件数量、文本长度、模型名称、系统提示词和请求字段均需有界校验。
- API Key、管理员密码、学生初始密码不得进入日志、快照或浏览器响应。
- 管理员启动凭据可以使用 Windows DPAPI 保存：API 地址、模型、管理员邮箱和管理员密码保存于本机安装数据；换 Windows 用户或电脑时无法解密，应提示重新输入。网页登录仍必须正常验证。

## 7. 部署和运维需求

- 提供 Windows 便携式 Python 和依赖，教师通过 `启动课堂.cmd`、`停止课堂.cmd` 操作，不要求教师手工运行 Python。
- 第一次启动填写提供商地址、模型和 API Key；成功后自动记忆，管理员邮箱和密码也自动记忆。
- 修改 API 配置使用 `修改模型配置.cmd`；修改管理员启动凭据使用 `Reset-SavedTeacherLogin.cmd`。
- 将整合包复制到另一台电脑时，DPAPI 密钥不能跨 Windows 用户解密；程序必须提示重新填写，而不是直接报错。
- 机房电脑需要安装/修复 Microsoft Visual C++ x64 运行库；`torch_python.dll` 报 WinError 126 时先处理此依赖。
- 更新程序文件应先停止课堂，再合并覆盖 `app`、`web` 和 `scripts`；不需要重新初始化，不得删除 `data`。
- `data` 包含账号、聊天、名册、附件、课堂设置和审计信息，不能在不备份的情况下覆盖。
- 服务重启后恢复未完成状态，不能重复扣次或重复调用模型；端口、路径和配置不能依赖开发机固定路径。
- 备份应包含课堂库、原生账号/聊天库、上传文件、必要安装密钥和 legacy 快照，并在恢复前校验哈希与 SQLite 完整性。

## 8. 数据和接口概要

核心数据包括：学生名册、认证会话、安全状态、每日额度、额度调整、审核请求、原始/有效快照、响应事件、附件、导入批次/行、教师操作审计和课堂设置。

主要接口包括：

- 学生：`/api/classroom/v1/me`、`/requests`、`/requests/{id}`、`/events`、`/delivery`、`/cancel`、附件上传、首次改密。
- 教师：学生列表、审核队列、审核决定/批量决定、停止请求、额度预览/调整、暂停课堂、名册预览/提交、单独添加学生、导出、重置密码、审计、模型策略、系统提示词与审计提示词 GET/PUT、审核模式、访客链接、使用概况、AI 审计历史。
- 访客：临时 Bearer 会话与流式聊天补全（不占学生额度、不经审核队列）。
- 内部桥接：身份准备/验证、文件关联和解析、签名运行时维护。

教师系统提示词更新请求示例：

```json
{
  "prompt": "你是耐心的编程老师，先引导学生思考，再解释原因。",
  "expected_version": 3
}
```

## 9. 质量验收标准

- 学生未批准的问题绝不进入提供商；学生不能通过原生模型路由绕过课堂服务。
- 额度在拒绝、主动停止、失败、重启、跨日和同操作重试场景下符合规则。
- 30 名学生同时提问时，身份、排队、审核、额度和单次模型调用保持一致。
- 刷新、关闭浏览器、局域网短暂中断和服务重启后，状态可恢复且不会重复扣次。
- 名册预览显示逐行错误；无有效行不能提交；有效行可安全导入；不符合格式的账号不会创建。
- 学生登录、首次改密、教师审核、教师改额度、教师重置密码和导出权限均按角色隔离。
- 学生端 Markdown 渲染不执行 HTML、脚本、危险链接或远程图片。
- 系统提示词版本冲突能提示重新加载；修改后新对话采用新提示词，旧快照不改变。
- 便携包在开发电脑和机房电脑均能启动；缺少 VC++ 运行库时给出可操作诊断。

## 10. 当前实现状态

截至 2026-09-19（2.1.8 测试候选），下列能力已在源码中实现，并以便携完整包形式交付（由 `scripts/Build-Package.ps1` 生成，例如 `release/openwebui-classroom-2.1.8-windows-x64.zip`）：课堂审核状态机与审核模式 teacher/ai/none、每日额度、教师批量额度、CSV 与单人导入、首次改密、文件与图片支持、审计/导出、暂停控制、Windows 便携包、教师直接对话、DPAPI 启动配置记忆、学生/访客对话 UI、Markdown 安全渲染、学生列表分页、审核原文展示、系统提示词与 AI 审计提示词、学生 events 流式回答、提问 1000 字限制、使用概况词云（仅已通过审核）、AI 审核短重试与教师队列轻量刷新。

公开源码见 GitHub；机房部署以完整 ZIP 解压为准。覆盖更新程序文件时先停止课堂，再合并 `app`/`web`/`scripts`，不要删除 `data`；浏览器建议 Ctrl+F5。现场验收边界见 [IMPLEMENTATION_STATUS.md](../IMPLEMENTATION_STATUS.md)。

## 11. 后续可选增强

这些内容不是当前必须项：

- 教师端可视化模型连接管理，而不只是配置脚本。
- 多模型下拉选择，并让不同模型绑定不同系统提示词。
- 教师公告、课堂时间段和更详细的使用统计图表。
- 学生组别/多班级、多教师协作。
- 独立的教学模板/Prompt 库和可按班级授权的模型预设。
- 自动更新与从旧整合包一键迁移向导。
